# Nexus Admin Tools 1.8.2: network code review

## Идентификация и права

Версия протокола 181. Требуется точная версия Nexus Admin Tools на сервере и каждом клиенте (`EveryoneMustHaveMod`, строгая patch-совместимость). Запросы идут по прямому `ZRpc` подключённого игрового peer. Сервер проверяет соединение, готовность peer, socket и host ID по серверному списку администраторов при каждом изменяющем действии. Переданные клиентом UID и RPC-маршруты не дают права на выполнение. Пакет ограничен 16 KiB; ID запросов монотонны на подключение, действия ограничены частотой, автоматического повтора изменяющей команды по таймауту нет.

Ответ связывается с ожидающими RPC, ID, действием и сроком. Клиент обрабатывает его только от текущего сервера, потребляет запрос до callback и отключает локальные эффекты после истечения разрешения. Клиентский poll раз в секунду передаёт состояния режимов только после получения прав; серверный журнал фиксирует переключения и множители.

## Новые команды мира

- **Погода:** авторизованный клиент отправляет имя окружения. Сервер проверяет его по `EnvMan.m_environments`, сохраняет по UID мира и вызывает `SetForceEnvironment`. В каждом ответе сервера передаётся текущее значение (пустое — динамическая погода), поэтому клиенты применяют тот же режим локально. Обычный игрок не может менять погоду.
- **Набеги:** сервер хранит флаг по миру, снимает текущий рейд и на серверной копии `RandEventSystem` блокирует начало будущих случайных/принудительных рейдовых событий. Обычные не-рейдовые принудительные события пропускаются. Включение возвращает обычное поведение.
- **Локации и телепорт:** сервер читает `ZoneSystem.GetLocationList()` после полного прохода генератора локаций по всей карте (`LocationsGenerated`), отбирает уникальные координаты и отправляет по 9 строк за страницу. Фильтр `m_placed` намеренно не используется: он показывает только зоны, которые уже загружались, и исключал неизвестные места. Клиент запрашивает лишь текущую страницу; в пакет не помещается весь каталог и повторного поиска мира на каждом клике нет. Для телепорта сервер сопоставляет присланный стабильный ключ и координаты со своей текущей страницей локаций; пользовательские точки берутся из сохранённого сервером списка. Точка возврата сохраняется на сервере для UID администратора; запрос возврата не принимает координаты от клиента. Сервер возвращает проверенную позицию, а владелец персонажа запускает штатный `Player.TeleportTo`.
- **Точки и имена:** команда добавления принимает от клиента только короткое имя. Координаты считываются сервером из актуального ZDO персонажа администратора, проверяются на допустимый диапазон и связываются с новым случайным GUID. Список и переименования хранятся в настройке BepInEx, привязанной к UID мира, и выдаются только после проверки прав. Переименование сгенерированной локации меняет только подпись Nexus; пустое имя сбрасывает её на исходную. Удаление разрешено только для ключа пользовательской точки, который найден в серверном списке; сгенерированные локации удалить нельзя. Сервер сохраняет каждое успешное изменение и записывает команду в общий журнал.
- **Общий журнал:** создаётся только после успешной проверки прав для команды. В записи есть UTC-время, день мира, имя/UID администратора, действие, параметры и результат. Записи ограничены по длине и числу, файл ограничен ротацией; чтение журнала постраничное. Запросы чтения и списка локаций сами не добавляют записи в журнал.
- **Бесконечная сила босса:** остаётся локальным эффектом подтверждённого администратора. Он сбрасывает cooldown лишь для локального игрока; сетевые команды мира из этого режима не выполняются.

## Очистка существ на выделенном сервере

Клиент передаёт до 200 ID видимых целей только как подсказки. После проверки администратора сервер получает позицию из ZDO персонажа, проверяет свои ZDO, зарегистрированный префаб Character без Player, расстояние, здоровье, тип босса и приручённость. Сервер группирует разрешённые цели по текущему ZDO owner и посылает прямой приказ каждому владельцу. Владелец проверяет, что отправителем является его игровой сервер, затем повторно проверяет ZDO, радиус, ограничения, локальный экземпляр и `IsOwner`; штатное `Character.SetHealth(0)` запускает обычную смерть и репликацию. Игроки исключаются всегда. Перемена владельца между проверками может пропустить цель; сообщение показывает отправку, а не подтверждённое число смертей.

Остальные команды мира также выполняются сервером. Спавн проверяет префаб, число, звёзды, имя и расстояние. Время меняется серверным `SetNetTime` только вперёд. Навыки, лечение и предметы применяются локально лишь после одноразового разрешения сервера. Скрытность меняет только проверку враждебности «моб → скрытый игрок», поэтому атака администратора по мобу остаётся возможной.

## Автоматическая и ручная проверка

Тесты проверяют правила протокола, имена и сброс алиасов, добавление/переименование/удаление точек по авторизованной серверной команде, сохранение серверного состояния, границы координат, защиту/доставку очистки, Namekeeper-переименования, сохранение Format 2, IL собранной DLL и доступность игровых API. Эти проверки не заменяют реальный запуск Unity. Живой игровой и сетевой тест этой версии не запускался; ручной план — `TEST_PLAN_1.8.2_RU.md`.
